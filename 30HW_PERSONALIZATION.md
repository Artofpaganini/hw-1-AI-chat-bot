# Функционал персонализации AI Chat

## Промпт

Ты — старший Android-разработчик (Kotlin, Jetpack Compose), а так отлично разбираешься в работе с настройкой/работой с RAG/MCP/SYSTEM_Tools. 
Есть проект мобильного приложения Ai-Chat-Bot, может взаимодействовать с:

-со сторонними Ai(deepseek/ gpt-5 и тп)

Требование - создать функционал персонализации, на основе которого Ai chat будет понимать с каким юзером он разговаривает  

1)Добавить функционал MCP сервер, для работы с БД - Room, с взаимосвязанными таблицами
- таблицы юзер с уникальный id и промптом под него(персонализация юзера)
- таблица контекстом от пользователя. Каждое сообщение должно быть ai  chatом и положено в БД. в виде строки, с максимум 5 словами, к примеру "Про эверест и восхождение к нему". Каждый контекст имеет общий ключ с таблицей юзер (к примеру его Id )

2)Краткое описание логики работы следующее user -> ai chat -> MCP(работает с бд)  -> ai chat -> user

1)Юзер заходит в приложение, и пишет что нибудь ai chat
2)ai chat определяет контекст сообщения юзера и спрашивает у MCP об этом контекста 
3)MCP ищет что то похожее в БД, в таблице контекста
 - если нашел, то поэтому контексту определяет  user_id и промпт для пользователя(варианты описаны ниже) и  отдает их ai chat 
 - если контекст +- совпадает с каким либо еще, то добавляет в таблицу + указывает user_id, на которых похож и  отдает их ai chat 
 - если ничего подобного нет, то создает кладет как новый контекст и создает нового user_id и промпт-сообщения юзера и отдает их ai chat 
4)ai chat получает юзер id и системный промпт и на основе него отвечает в таком же стиле, и сам предлагает вещи на основе контекста
5) ai chat  отвечает пользователю

## Что было сделано

### 1. База данных (Room)

#### Созданы новые Entity:

**UserEntity** (`core/database/entity/UserEntity.kt`)
- `id: String` - уникальный идентификатор пользователя
- `personalizationPrompt: String` - промпт персонализации для пользователя
- `createdAt: Long` - время создания

**UserContextDao** (`core/database/dao/UserContextDao.kt`)

- `findExactContext(contextPattern: String)` - поиск точного совпадения
- `insertContext(context: UserContextEntity)` - вставка контекста
- `getAllContexts()` - получение всех контекстов

### 3. Data Layer

#### Реализация репозитория:

**PersonalizationRepositoryImpl** (`feature/chat/data/repository/PersonalizationRepositoryImpl.kt`)

Логика работы:
1. **Нормализация контекста**: Приводит контекст к нижнему регистру, разбивает на слова и берет максимум 5 слов
2. **Поиск точного совпадения**: Ищет в БД контекст, похожий на текущий
3. **Если найдено точное совпадение**: Возвращает существующий профиль пользователя
4. **Если найдены похожие контексты**: Создает нового пользователя с промптом, основанным на похожих пользователях, и сохраняет контекст
5. **Если ничего не найдено**: Создает нового пользователя с базовым промптом и сохраняет контекст

**Генерация промпта персонализации**:
- Если найден похожий пользователь: объединяет его промпт с новым контекстом
- Если пользователь новый: создает базовый промпт с описанием интересов пользователя

### 4. Use Cases

#### PersonalizeUserUseCase (`feature/chat/domain/usecase/PersonalizeUserUseCase.kt`)

**Функционал**:
1. Извлекает контекст из сообщения пользователя с помощью AI (максимум 5 слов)
2. Использует PersonalizationRepository для поиска/создания профиля пользователя
3. Сохраняет контекст в БД
4. Возвращает UserProfile с промптом персонализации

**Извлечение контекста**:
- Использует AI модель (по умолчанию DeepSeek) для извлечения основной темы из сообщения
- Запрашивает краткое описание темы максимум в 5 словах на русском языке
- Нормализует результат (обрезает до 5 слов, приводит к нижнему регистру)

## Принцип работы

### Поток данных:

```
User -> ChatViewModel -> PersonalizeUserUseCase -> AI (извлечение контекста)
                                                    ↓
                                    PersonalizationRepository -> Room DB
                                                    ↓
                                    (поиск/создание профиля)
                                                    ↓
                                    ChatViewModel -> SendMessageUseCase
                                                    ↓
                                    AI (ответ с персонализацией)
                                                    ↓
                                    User
```

### Детальный алгоритм:

1. **Пользователь отправляет сообщение**
   - Сообщение сохраняется в БД как обычное сообщение чата

2. **Извлечение контекста**
   - `PersonalizeUserUseCase` отправляет запрос к AI для извлечения основной темы (максимум 5 слов)
   - Пример: "Расскажи про Эверест и как на него взобраться" → "Про Эверест и восхождение"

3. **Поиск в БД (MCP-подобная логика)**
   - `PersonalizationRepository` ищет похожий контекст в таблице `user_contexts`
   - **Вариант 1 - Точное совпадение**: Если найден похожий контекст, возвращается существующий `user_id` и его промпт
   - **Вариант 2 - Похожий контекст**: Если найдены похожие контексты, создается новый пользователь с промптом, основанным на похожих пользователях, и сохраняется новый контекст
   - **Вариант 3 - Новый контекст**: Если ничего не найдено, создается новый пользователь с базовым промптом и сохраняется контекст

4. **Формирование системного промпта**
   - Промпт персонализации добавляется в системное сообщение
   - AI получает инструкции отвечать с учетом интересов пользователя и предлагать релевантные темы

5. **Ответ AI**
   - AI генерирует ответ с учетом персонализации
   - Ответ сохраняется в БД

## Решение проблем

### Проблема: Ошибка миграции базы данных

**Решение**: База данных настроена с `fallbackToDestructiveMigration(true)`, что означает, что при изменении схемы БД данные будут удалены. Для production следует создать миграцию:

```kotlin
val MIGRATION_2_3 = object : Migration(2, 3) {
    override fun migrate(database: SupportSQLiteDatabase) {
        database.execSQL("CREATE TABLE IF NOT EXISTS users (id TEXT NOT NULL PRIMARY KEY, personalizationPrompt TEXT NOT NULL, createdAt INTEGER NOT NULL)")
        database.execSQL("CREATE TABLE IF NOT EXISTS user_contexts (id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL, userId TEXT NOT NULL, context TEXT NOT NULL, createdAt INTEGER NOT NULL, FOREIGN KEY(userId) REFERENCES users(id) ON DELETE CASCADE)")
        database.execSQL("CREATE INDEX IF NOT EXISTS index_user_contexts_userId ON user_contexts(userId)")
        database.execSQL("CREATE INDEX IF NOT EXISTS index_user_contexts_context ON user_contexts(context)")
    }
}
```

### Проблема: AI не извлекает контекст корректно

**Решение**: 
- Проверьте, что API ключ для DeepSeek настроен в `local.properties`
- Улучшите промпт в `PersonalizeUserUseCase.extractContext()` для более точного извлечения
- Добавьте обработку ошибок и fallback на простое извлечение ключевых слов

### Проблема: Контекст не находится в БД

**Решение**:
- Проверьте логику поиска в `UserContextDao.findSimilarContexts()` - используется LIKE с `%pattern%`
- Улучшите нормализацию контекста в `PersonalizationRepositoryImpl.normalizeContext()`
- Рассмотрите использование полнотекстового поиска (FTS) для более точного поиска

### Проблема: Промпт персонализации не применяется

**Решение**:
- Проверьте, что `personalizeUserUseCase` вызывается перед `sendMessageUseCase`
- Убедитесь, что промпт добавляется в системное сообщение в `buildMessagesWithContext()`
- Проверьте логи, что промпт действительно передается в AI API
