## ⚠️ ВАЖНО: Публичный IP адрес обязателен!

**Критически важно:** VPS должен иметь **публичный IP адрес** для доступа в интернет!

- **Публичный IP:** `109.73.194.244`, `185.123.45.67` - работает для доступа из интернета ✅
- **Приватный IP:** `192.168.x.x`, `10.x.x.x` - НЕ работает для доступа из интернета ❌

**Где найти публичный IP:**
- В панели управления VPS на вкладке **"Сеть"** → **"IP-адреса"**
- Ищите адрес, который НЕ начинается с `192.168.`, `10.`, `172.16.`
- **Пример:** `109.73.194.244` - это публичный IPv4 адрес

**Если VPS не имеет публичного IP:**
- Свяжитесь с поддержкой VPS провайдера
- Попросите предоставить публичный IPv4 адрес
- Обычно это бесплатная услуга или включена по умолчанию

**После получения публичного IP:**
- Используйте его для SSH: `ssh root@109.73.194.244`
- Используйте его в Android приложении: `http://109.73.194.244:11434`

## Принцип работы

### Архитектура

```
Android App (ChatViewModel)
    ↓
AiModelRepositoryImpl
    ↓
VpsOllamaApi (Retrofit)
    ↓
VPS Server (http://your-vps-ip:11434)
    ↓
Ollama Server (localhost:11434)
    ↓
Local LLM Model (llama3.2:3b)
```

### Поток данных

1. Пользователь настраивает VPS URL в ToolsDialog (⚙️)
2. URL сохраняется в `PreferencesManager` (SharedPreferences)
3. Пользователь выбирает модель "VPS - Ollama: llama3.2:3b" из выпадающего списка
4. При отправке сообщения:
   - `ChatViewModel` вызывает `sendMessageUseCase`
   - `SendMessageUseCase` вызывает `aiModelRepository.sendMessage()`
   - `AiModelRepositoryImpl` определяет, что выбрана модель `VpsOllama`
   - Получает VPS URL из `PreferencesManager`
   - Создает `VpsOllamaApi` с динамическим URL
   - Преобразует сообщения в формат Ollama (`OllamaChatMessage`)
   - Отправляет запрос на VPS сервер через `VpsOllamaApi.generateChat()`
   - Обрабатывает ответ и возвращает `AiResponse`
5. Ответ отображается в UI

### ШАГ 2: Подключение к VPS серверу по SSH

#### 2.0. ⚠️ ВАЖНО: Настройте Firewall для SSH (порт 22) ПЕРЕД подключением!

**Если получаете ошибку "Operation timed out" при SSH подключении:**

1. **Откройте панель управления VPS**
2. **Перейдите на вкладку "Сеть" → "Firewall"**
3. **Создайте правило для входящих соединений на порт 22 (SSH):**
   - **Направление:** Входящий трафик (Incoming/Inbound)
   - **Протокол:** TCP
   - **Порт:** `22`
   - **Действие:** Разрешить (Allow)
   - **Описание:** SSH access
4. **Сохраните и примените правило**

**Без этого правила SSH не будет работать!**

#### 2.1. Откройте терминал на вашем компьютере

- **Mac/Linux:** Откройте приложение "Терминал" (Terminal)
- **Windows:** Используйте PowerShell или установите Git Bash / WSL

#### 2.2. Подключитесь к VPS по SSH

**ВАЖНО:** Для IPv6 адреса обязательно используйте квадратные скобки `[...]`!

**Для IPv4 адреса (публичный IP):**
```bash
ssh root@ваш-публичный-ip-адрес
# Пример: ssh root@109.73.194.244
# НЕ используйте приватный IP (192.168.x.x, 10.x.x.x)!
# Публичный IP начинается НЕ с 192.168., 10., 172.16.
```

**Если получаете ошибку "Operation timed out":**
- Проверьте, что в firewall разрешены входящие соединения на порт 22 (см. шаг 2.0 выше)
- Или используйте веб-консоль VPS (см. шаг 2.3 ниже)

**Для IPv6 адреса (ОБЯЗАТЕЛЬНО с квадратными скобками):**
```bash
ssh root@[ваш-ipv6-адрес]
# Пример: ssh root@[2a03:6f00:a::1:a92c]
# НЕ ПРАВИЛЬНО: ssh root@2a03:6f00:a::1:a92c (без скобок - будет ошибка!)
```

**Для доменного имени:**
```bash
ssh root@ваш-домен
# Пример: ssh root@vps.example.com
```

**Если получаете ошибку "Operation timed out":**

1. **Проверьте firewall в панели управления VPS:**
   - Перейдите на вкладку "Сеть" → "Firewall"
   - Убедитесь, что есть правило для входящих соединений на порт 22 (TCP)
   - Если нет - создайте правило (см. шаг 2.0 выше)

2. **Используйте веб-консоль VPS:**
   - Откройте панель управления VPS
   - Найдите кнопку "Веб-консоль" (Web Console)
   - Используйте веб-консоль для всех операций (не требует SSH)

**Если получаете ошибку "No route to host" при IPv6:**

1. **Проверьте, что используете квадратные скобки:**
   ```bash
   # ПРАВИЛЬНО:
   ssh root@[2a03:6f00:a::1:a92c]
   
   # НЕПРАВИЛЬНО (вызовет ошибку):
   ssh root@2a03:6f00:a::1:a92c
   ```

2. **Проверьте поддержку IPv6 на вашем компьютере:**
   ```bash

   # Или
   ping6 -c 3 [2a03:6f00:a::1:a92c]
   ```

3. **Если IPv6 не работает, попробуйте найти IPv4 адрес:**
   - Проверьте вкладку "Сеть" в панели управления VPS
   - Проверьте вкладку "Доступ" в панели управления VPS
   - Свяжитесь с поддержкой VPS провайдера для получения IPv4 адреса

### ШАГ 3: Установка Ollama на VPS сервере

#### 3.1. Убедитесь, что вы подключены к VPS

Вы должны видеть приглашение командной строки вида `root@сервер:~#`

#### 3.2. Проверьте интернет-соединение на VPS

**ВАЖНО:** Перед установкой Ollama убедитесь, что VPS имеет доступ в интернет.

**Шаг 1: Проверка базового подключения**

Выполните команду для проверки:
```bash
ping -c 3 8.8.8.8
```

**Если ping работает:**
- Вы увидите ответы вида:
  ```
  PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
  64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=15.2 ms
  64 bytes from 8.8.8.8: icmp_seq=2 ttl=118 time=14.8 ms
  64 bytes from 8.8.8.8: icmp_seq=3 ttl=118 time=15.1 ms
  ```
- **Интернет работает!** Продолжайте установку

**Если ping не работает:**
- Ошибка "Network is unreachable" или "Destination Host Unreachable"
- **VPS не имеет доступа в интернет**
- См. раздел "Решение проблем с интернет-соединением" ниже

**Шаг 2: Проверка DNS**

Если ping работает, проверьте DNS:
```bash
nslookup google.com
```

**Если DNS работает:**
- Вы увидите IP адрес
- DNS работает, продолжайте установку Ollama

**Если DNS не работает (ошибка "Could not resolve host"):**
- Это означает, что DNS серверы не настроены
- Установите DNS серверы Google (см. ниже)

**Решение проблемы DNS:**

Если получаете ошибку `curl: (6) Could not resolve host: ollama.com`:

1. **Проверьте текущие DNS настройки:**
   ```bash
   cat /etc/resolv.conf
   ```

2. **Установите DNS серверы Google:**

   **Для Ubuntu/Debian:**
   ```bash
   # Временная настройка (до перезагрузки)
   echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf
   echo "nameserver 8.8.4.4" | sudo tee -a /etc/resolv.conf
   ```
   
   **ВАЖНО:** Если видите предупреждение:
   ```
   sudo: unable to resolve host ...: Temporary failure in name resolution
   ```
   **Это не ошибка!** Это просто предупреждение. Команды выполнились успешно, если вы видите `nameserver 8.8.8.8` и `nameserver 8.8.4.4` в выводе.
   
   # Постоянная настройка (после перезагрузки)
   sudo nano /etc/systemd/resolved.conf
   # Раскомментируйте и измените строки:
   # DNS=8.8.8.8 8.8.4.4
   # FallbackDNS=1.1.1.1
   sudo systemctl restart systemd-resolved
   ```

   **Для CentOS/RHEL:**
   ```bash

   echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf
   echo "nameserver 8.8.4.4" | sudo tee -a /etc/resolv.conf
   
   # Постоянная настройка
   sudo nano /etc/sysconfig/network-scripts/ifcfg-eth0
   # Добавьте строки:
   # DNS1=8.8.8.8
   # DNS2=8.8.4.4
   sudo systemctl restart network
   ```

3. **Проверьте, что DNS настройки применились:**
   ```bash
   cat /etc/resolv.conf
   ```
   
   Должны увидеть:
   ```

   nameserver 8.8.4.4
   ```

4. **Проверьте работу DNS:**
   ```bash

   ```
   
   Должен вернуться IP адрес. Если работает - DNS настроен!

5. **Если DNS работает, попробуйте установить Ollama:**
   ```bash

   ```
   
   **Если все еще ошибка "Could not resolve host":**
   - Подождите 10-20 секунд после настройки DNS
   - Попробуйте снова: `curl -fsSL https://ollama.com/install.sh | sh`

### ШАГ 6: Настройка firewall (открытие порта 11434)

#### 6.1. Настройка Firewall через панель управления VPS

**ВАЖНО:** Если в панели управления VPS в разделе "Сеть" → "Firewall" написано "У вас еще нет созданных групп правил", нужно настроить firewall!

**Шаг 1: Настройка Firewall в панели управления**

1. **В панели управления VPS на вкладке "Сеть":**
   - Найдите секцию **"Firewall"**
   - Нажмите кнопку **"Настроить"** (Configure)

2. **Создайте правило для исходящих соединений:**
   - Создайте новую группу правил
   - **ВАЖНО:** Добавьте несколько правил:
     
     **Правило 1: ICMP (для ping):**
     - **Тип:** Исходящий трафик (Outbound)
     - **Протокол:** ICMP (не TCP!)
     - **Порт:** НЕ УКАЗЫВАЙТЕ (ICMP не использует порты - это протокол сетевого уровня)
     - **Действие:** Разрешить (Allow)
     - **ВАЖНО:** 
       - ICMP не требует указания порта - оставьте поле "Порт" пустым или не заполняйте его
       - Без этого правила ping не будет работать!
     
     **Правило 2: TCP (для HTTP/HTTPS):**
     - **Тип:** Исходящий трафик (Outbound)
     - **Протокол:** TCP
     - **Порт:** Все порты (All ports) или конкретные: 80, 443
     - **Действие:** Разрешить (Allow)
     - **ВАЖНО:** Убедитесь, что поле "Порт" заполнено!
     
     **Правило 3: UDP (для DNS):**
     - **Тип:** Исходящий трафик (Outbound)
     - **Протокол:** UDP (не TCP!)
     - **Порт:** 53
     - **Действие:** Разрешить (Allow)
     - **ВАЖНО:** Без этого правила DNS не будет работать! Если видите ошибку "UDP setup failed: network unreachable" - это значит, что правило для UDP порта 53 отсутствует.
   - Сохраните все правила
   - Примените правила (нажмите "Применить" или "Сохранить")

3. **Создайте правило для входящих соединений на порт 22 (SSH):**
   - Добавьте правило:
     - **Тип:** Входящий трафик (Inbound)
     - **Протокол:** TCP
     - **Порт:** `22`
     - **Действие:** Разрешить (Allow)
     - **Описание:** SSH access
   - Сохраните правило
   - **ВАЖНО:** Без этого правила SSH не будет работать! Если получаете "Operation timed out" - это значит, что порт 22 заблокирован.

4. **Создайте правило для входящих соединений на порт 11434 (для Ollama):**
   - Добавьте правило:
     - **Тип:** Входящий трафик (Inbound)
     - **Протокол:** TCP
     - **Порт:** `11434`
     - **Адрес:** **Все адреса** (All addresses) - ВАЖНО для доступа из интернета!
     - **Действие:** Разрешить (Allow)
     - **Описание:** Ollama server
   - **ВАЖНО:** Если указать конкретный IP адрес (например, `37.45.128.226`), доступ будет только с этого IP. Для работы из Android приложения нужно разрешить доступ со всех адресов!
   - Сохраните правило

4. **Примените правила:**
   - Нажмите "Применить" или "Сохранить"
   - Дождитесь применения правил (обычно несколько секунд)

**Шаг 2: Проверка через веб-консоль**

После настройки firewall в панели управления, проверьте в веб-консоли:

```bash
# Проверка интернета
ping -c 3 8.8.8.8
```

Если ping работает - интернет настроен!

#### 6.2. Альтернатива: Настройка Firewall через веб-консоль

Если настройка через панель не работает, настройте через веб-консоль:

**Убедитесь, что вы во втором терминале VPS** (не в том, где запущен `ollama serve`)

**Проверьте, какая система установлена:**
```bash
cat /etc/os-release
```

**Для Ubuntu/Debian:**
```bash

# Если firewall не активен, активируйте его

# Разрешите исходящие соединения (важно для доступа в интернет!)

# Разрешите входящие соединения на порт 11434 (для Ollama)

# Примените изменения

# Проверьте статус

sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --permanent --add-service=dns

# Разрешите входящие соединения на порт 11434 (для Ollama)
sudo firewall-cmd --permanent --add-port=11434/tcp

# Примените изменения
sudo firewall-cmd --reload

# Проверьте правила
sudo firewall-cmd --list-all
```

## Решение проблем

### Проблема 1: Модель не отображается как настроенная

**Симптомы:**
- Модель "VPS - Ollama: llama3.2:3b" отмечена красным индикатором
- При попытке отправить сообщение появляется ошибка "VPS Ollama URL is not configured"

**Решение:**
1. Откройте настройки (⚙️)
2. Убедитесь, что VPS URL введен правильно
3. Проверьте формат URL (должен начинаться с `http://` или `https://`)
4. Закройте и снова откройте диалог настроек

### Проблема 2: Ошибка подключения к VPS серверу

**Симптомы:**
- Ошибка "Network error: Unable to connect to host"
- Ошибка "Connection timeout"
- Ошибка "Connection refused (ECONNREFUSED)"

**Решение:**
1. **Проверьте, что Ollama запущен на VPS сервере:**
   - В веб-консоли VPS: `ps aux | grep ollama | grep -v grep`
   - Если не запущен - запустите: `OLLAMA_HOST=0.0.0.0:11434 ollama serve`

2. **Проверьте, на каком интерфейсе слушает Ollama:**
   - В веб-консоли VPS: `sudo ss -tlnp | grep 11434` (если netstat не установлен)
   - **Должно быть `0.0.0.0:11434`, а не `127.0.0.1:11434`!**
   - Если видите `127.0.0.1:11434` - Ollama слушает только локально и недоступен извне
   - **Решение:** Остановите Ollama и запустите снова: `OLLAMA_HOST=0.0.0.0:11434 ollama serve`
   - Если `127.0.0.1:11434` - перезапустите с `OLLAMA_HOST=0.0.0.0:11434`

3. **Проверьте доступность Ollama с вашего компьютера:**
   - **Для IPv4:** `curl http://109.73.194.244:11434/api/tags` (замените на ваш публичный IP)
   - **Для IPv6:** `curl http://[2a03:6f00:a::1:a92c]:11434/api/tags`
   - Должен вернуться JSON с моделями
   - **Если возвращается `{"models":[]}`** - модель еще не установлена, установите ее: `ollama pull llama3.2:3b` (см. ШАГ 5)

4. **Проверьте firewall на VPS сервере:**
   - Порт 11434 должен быть открыт во **входящих** правилах firewall
   - Проверьте в панели управления VPS на вкладке "Сеть" → "Firewall"

5. **Проверьте правильность IP адреса и порта в настройках:**
   - Используйте публичный IP, а не приватный (192.168.x.x, 10.x.x.x)
   - Формат: `http://109.73.194.244:11434`

6. **Для IPv6:** Убедитесь, что используете формат с квадратными скобками: `http://[IPv6]:11434`

7. **Проверьте ping (для диагностики интернета):**
   - В веб-консоли VPS: `ping -c 3 8.8.8.8`
   - Если не работает - проверьте firewall для исходящего ICMP трафика

**Подробная инструкция по исправлению проблем:** 
- `VPS_OLLAMA_CONNECTION_FIX.md` - общая инструкция
- `VPS_OLLAMA_DIAGNOSTICS.md` - пошаговая диагностика (ping работает, но curl не работает)
- `VPS_OLLAMA_LOCALHOST_FIX.md` - исправление проблемы, когда Ollama работает локально, но недоступен извне
- `VPS_OLLAMA_MEMORY_ERROR_FIX.md` - исправление ошибки "model requires more system memory"
- `VPS_OLLAMA_CONNECTION_REFUSED_FIX.md` - исправление ошибки "Connection refused (ECONNREFUSED)"

### Проблема 3: Модель не найдена на VPS сервере

**Симптомы:**
- Ошибка "Model not found" или "Model llama3.2:3b not available"

**Решение:**
1. На VPS сервере проверьте установленные модели: `ollama list`
2. Если модель не установлена, установите её: `ollama pull llama3.2:3b`
3. Проверьте доступность модели: `curl http://your-vps-ip:11434/api/tags`

### Проблема 4: Медленные ответы

**Симптомы:**
- Ответы от VPS сервера приходят очень медленно

**Решение:**
1. Проверьте скорость интернет-соединения между Android устройством и VPS сервером
2. Проверьте нагрузку на VPS сервер
3. Рассмотрите использование более мощной модели или оптимизацию VPS сервера
