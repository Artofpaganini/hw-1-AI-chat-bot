Краткое описание логики работы Ollama,

1)Индексация указанных(пользователем) книг (не более 5). ( Если книга новая и только что добавлена )
- Получите эмбеддинг данные через Ollama API. Текст разбивается на чанки по 512 токенов с перекрытием 50 токенов
- Сохраните в БД, данные о книге, чтобы в будущем если она уже была добавлена не индесировать ее снова. К примеру имя - IndexedBooks. Структура: bookId, title, fileHash, chunkCount, timestamp
- Сохраните в БД данные после индексации(к примеру Room/Sqlite/любую векторную БД). Таблица эмбеддингов должна иметь связь с таблицей IndexedBooks, к примеру по bookId

2)При запросе пользователя ( Если книга новая и только что добавлена )
- Получите эмбеддинг запроса
- Найдите чанки-кандидаты по косинусному сходству

3) Reranking через LLM-as-a-reranker
- для каждого чанк - кандидата, сформируй промпт для оценки релевантности. Пример промпта
Оцени релевантность текста запросу по шкале от 0.0 до 1.0. Запрос: "Введенный пользователем" Источник: "Откуда был взят ответ" (Если источника нет - Указать "Неизвестный источник" Текст: "Текст на основании запроса" Ответь Название источника + текст + релевантность текста в виде "Релевантность число". Никаких пояснений.
4) Отдать ответ ai-chat
4)Полученные ответы и отсортируй их по убыванию( где 1 это макс релевантность), макс 5 самых релевантных чанков
5) Отдать ответ ai-chat

Краткое описание логики работы следующее user -> ai chat -> ollama(embedded/reranking)+бд -> ai chat

1)Юзер заходит в приложение, и:
- если инстументы ollama + свичер фильтранции (reranking) выключены, то ai-chat работает только от своего api
- инстументы ollama + свичер фильтранции (reranking) включены, то ai-chat в первую очередь работает с RAG, а значит функционал отображает уже загруженные книги. Если юзер указывает новую книгу, то приложение вычисляет SHA-256 хеш содержимого файла для идентификации дубликатов и проверяет в бд, к примеру по запросу в Room: SELECT * FROM IndexedBooks WHERE fileHash = ? , где:
  1. Если книга уже проиндексирована: Отображается уведомление: «Книга уже добавлена». Загрузка завершается.
  2. Если книга новая: то книга индексируеся и вяс информация сохраняется в бд, в таблицу IndexedBooks и таблицу Embedding. Таблицы должны быть завязаны на какой нибудь ключ к примеу bookId
3)Юзер пишет какой то вопрос в ai-chat
4) ai chat передает запрос ollama, в ней описана логика
- В Room выполняется запрос на поиск ближайших соседей (косинусное сходство). К примеру SELECT *, (embedding_0 * ? + embedding_1 * ? + ...) AS similarity FROM BookChunks WHERE bookId = ? ORDER BY similarity DESC LIMIT 10
Для эффективности: предварительная фильтрация по bookId, если контекст ограничен одной книгой.
4) Найденный, на основании chunks, ответ, ollama отдает ai-chat
5) ai-chat отдает, результат ответа на вопрос пользователя

## Как запустить

### Шаг 1: Настройка Ollama

1. **Установите и запустите Ollama:**
   ```bash
   ./setup-ollama.sh
   ```
   
   Этот скрипт:
   - Проверяет установку Ollama (устанавливает через Homebrew, если нужно)
   - Запускает Ollama сервер на `http://localhost:11434`
   - Скачивает embedding модель `nomic-embed-text`

2. **Установите модель для reranking:**
   ```bash
   ollama pull phi3:medium
   ```

3. **Проверьте подключение (для эмулятора):**
   ```bash
   ./test-ollama-connection.sh
   ```

### Шаг 2: Сборка и запуск приложения

1. **Соберите приложение:**
   ```bash
   ./gradlew assembleDebug
   ```

2. **Установите на эмулятор/устройство:**
   ```bash
   adb install app/build/outputs/apk/debug/app-debug.apk
   ```

3. **Запустите приложение** на эмуляторе или устройстве.

### Шаг 3: Настройка в приложении

1. **Откройте приложение** на эмуляторе/устройстве
2. **Нажмите на иконку настроек** (⚙️) в верхней панели
3. **Включите Ollama:**
   - Включите "Ollama Vector Search" (switcher)
   - При первом включении запросятся разрешения на чтение файлов
   - После предоставления разрешений switcher автоматически включится
4. **Включите Reranking (опционально):**
   - Включите "Reranking (Filtering)" для использования LLM-as-a-Reranker
   - Требует установленную модель `phi3:medium`

### Шаг 4: Индексация документов

1. **Выберите файлы для индексации:**
   - Нажмите "Select File"
   - Выберите до 5 файлов (.md, .txt)
   - Каждый файл будет автоматически проиндексирован

2. **Проверка дубликатов:**
   - Если файл уже был проиндексирован (проверка по SHA-256 хешу), появится уведомление "Книга уже добавлена"
   - Индексация не будет повторяться для того же файла

3. **Проверьте логи:**
   - Откройте Logcat в Android Studio
   - Фильтр: `TextIndexingService` или `VectorDatabaseService`
   - Должны быть логи о процессе индексации и сохранении в БД

### Шаг 5: Использование RAG

1. **Задайте вопрос в AI chat:**
   - Вопрос должен быть связан с содержимым проиндексированных документов
   - AI будет использовать контекст из документов для ответа

2. **С Ollama и Reranking включенными:**
   - Выполняется поиск до 10 кандидатов через embeddings
   - Для каждого кандидата выполняется reranking через `phi3:medium`
   - Выбираются топ-5 самых релевантных чанков
   - В ответе указываются источники (названия книг) и оценки релевантности
   - В конце ответа фраза **"С Ollama и фильтрацией"**

3. **С Ollama включенным, но Reranking выключенным:**
   - Выполняется поиск до 10 кандидатов через embeddings
   - Выбираются топ-5 чанков по косинусному сходству
   - В конце ответа фраза **"С Ollama и без фильтрацией"**

4. **С Ollama выключенным:**
   - AI формирует ответ самостоятельно
   - В конце ответа фраза **"Без Ollama"**

## Принцип работы

### Архитектура

```
User -> AI Chat -> Ollama (embeddings/reranking) + Room DB -> AI Chat -> User
```

### Поток данных

1. **Индексация (при добавлении нового файла):**
   ```
   Файл -> SHA-256 хеш -> Проверка в БД (IndexedBooks по fileHash)
   -> Если новый: Чанкинг (512 токенов, перекрытие 50) 
   -> Генерация embeddings (nomic-embed-text) 
   -> Сохранение в Room БД (IndexedBooks + BookChunks)
   ```

2. **Запрос пользователя:**
   ```
   Запрос -> Embedding запроса (nomic-embed-text)
   -> Поиск в БД (косинусное сходство в Kotlin)
   -> До 10 кандидатов
   ```

3. **Reranking (если включен):**
   ```
   Кандидаты -> Промпт для каждого (phi3:medium)
   -> Оценка релевантности (0.0-1.0)
   -> Сортировка по убыванию
   -> Топ-5 чанков
   ```

4. **Генерация ответа:**
   ```
   Топ-5 чанков -> Контекст для AI chat
   -> Ответ от AI chat (DeepSeek/Claude/GPT/Gemini)
   -> Сохранение в историю (ChatMessageEntity)
   -> Отображение пользователю
   ```

### Структура БД

**IndexedBooks:**
- `bookId` (PK, AutoGenerate)
- `title` (название файла)
- `fileHash` (SHA-256, уникальный)
- `chunkCount` (количество чанков)
- `timestamp` (время индексации)

**BookChunks:**
- `chunkId` (PK, AutoGenerate)
- `bookId` (FK к IndexedBooks)
- `chunkIndex` (индекс чанка в книге)
- `chunkText` (текст чанка)
- `embedding` (JSON массив Float)

**ChatMessages:**
- `messageId` (PK, AutoGenerate)
- `content` (текст сообщения)
- `isUser` (Boolean)
- `model` (String, название модели)
- `timestamp` (Long)

## Решение проблем

**Проблема: "Книга уже добавлена" при попытке добавить новый файл**
- **Решение:** Это нормальное поведение. Файл с таким же содержимым (SHA-256 хеш) уже проиндексирован. Если нужно переиндексировать, удалите книгу из БД через экспорт JSON и очистку БД.

**Проблема: "Failed to generate embedding"**
- **Решение:**
  1. Проверьте, что Ollama сервер запущен: `curl http://localhost:11434/api/tags`
  2. Проверьте, что модель установлена: `ollama list | grep nomic-embed-text`
  3. Проверьте подключение из эмулятора: `adb shell curl http://10.0.2.2:11434/api/tags`

**Проблема: Индексация не завершается**
- **Решение:**
  1. Проверьте логи приложения (Logcat)
  2. Убедитесь, что Ollama сервер доступен
  3. Проверьте размер файла (большие файлы могут индексироваться долго)
  4. Проверьте, что в БД достаточно места

**Проблема: Reranking не работает**
- **Решение:**
  1. Убедитесь, что модель `phi3:medium` установлена: `ollama pull phi3:medium`
  2. Проверьте, что reranking включен в настройках
  3. Проверьте логи приложения на наличие ошибок при reranking

**Проблема: История не сохраняется**
- **Решение:**
  1. Проверьте, что Room БД инициализирована корректно
  2. Проверьте логи на наличие ошибок при сохранении
  3. Убедитесь, что приложение имеет права на запись в БД

**Проблема: Поиск не находит релевантные чанки**
- **Решение:**
  1. Проверьте, что файлы проиндексированы (проверьте таблицу IndexedBooks)
  2. Убедитесь, что embeddings сгенерированы корректно
  3. Проверьте, что поиск выполняется в правильных файлах (проверьте `ollamaSelectedFiles`)

## Технические детали

### Зависимости

- **Room 2.6.1** - для работы с БД
- **Gson** - для сериализации `List<Float>` в JSON
- **Kotlin Coroutines** - для асинхронных операций
- **Retrofit + OkHttp** - для работы с Ollama API

### Производительность

- **Индексация:** Зависит от размера файла. Для файла ~100KB индексация занимает ~30-60 секунд.
- **Поиск:** Поиск по БД выполняется быстро благодаря предварительной фильтрации по `bookId`.
- **Reranking:** Зависит от количества кандидатов. Для 10 кандидатов reranking занимает ~5-10 секунд.
