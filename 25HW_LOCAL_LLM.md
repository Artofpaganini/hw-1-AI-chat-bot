## Что было сделано

### 1. Исправлена модель по умолчанию для чата

**Проблема:** `DEFAULT_CHAT_MODEL` был установлен на `nomic-embed-text`, что является embedding моделью, а не chat моделью.

**Решение:**
- Изменен `DEFAULT_CHAT_MODEL` в `OllamaApi.kt` на `llama3.2:3b` (быстрая и легкая chat модель)
- Исправлен `SendRagMessageUseCase` для использования правильной модели по умолчанию

### 2. Добавлена поддержка выбора локальной LLM модели

**Реализовано:**
- Добавлено поле `ollamaChatModel` в `PreferencesManager` для хранения выбранной модели
- Добавлены поля в `ChatUiState`: `availableOllamaModels` и `selectedOllamaChatModel`
- Добавлен метод `loadOllamaModels()` для загрузки списка доступных моделей через API
- Добавлен обработчик `SelectOllamaChatModel` для выбора модели
- Автоматическая загрузка моделей при включении Ollama

### 3. Реализовано использование Ollama для обычного чата

**Реализовано:**
- Добавлен метод `handleSendMessageWithOllamaChat()` для обычного чата через Ollama
- Модифицирован `handleSendMessageWithOllama()`:
  - Если есть индексированные документы → используется RAG с Ollama
  - Если нет индексированных документов → используется обычный чат через Ollama
- Использование истории сообщений для контекста (последние 10 сообщений)
- Использование выбранной локальной модели для генерации ответов

### 4. Обновлен UI для выбора модели

**Реализовано:**
- Добавлен dropdown для выбора локальной модели в `ToolsDialog`
- Отображение списка доступных моделей из Ollama
- Автоматическое обновление списка при включении Ollama
- Визуальная индикация выбранной модели

### 5. Созданы скрипты для установки и проверки моделей

**Скрипты:**
- `setup-ollama.sh` - обновлен для установки моделей по умолчанию (`llama3.2:3b`, `phi3:medium`)
- `install-ollama-models.sh` - новый скрипт для установки и проверки моделей:
  - Интерактивный режим выбора моделей
  - Автоматическая установка моделей по умолчанию
  - Тестирование установленных моделей

## Флоу запуска

### Шаг 1: Установка и запуск Ollama

```bash
# Установка Ollama и моделей по умолчанию
./setup-ollama.sh
```

**Что делает скрипт:**
1. Проверяет установку Ollama (устанавливает через Homebrew, если нужно)
2. Запускает Ollama сервер на `http://localhost:11434`
3. Устанавливает embedding модель `nomic-embed-text`
4. Устанавливает модели для чата: `llama3.2:3b` и `phi3:medium`

### Шаг 2: Установка дополнительных моделей (опционально)

```bash
# Интерактивный режим
./install-ollama-models.sh --interactive

# Или установка конкретной модели
ollama pull llama3:8b
ollama pull mistral:7b
```

### Шаг 3: Проверка работы Ollama

```bash
# Проверка доступности сервера
curl http://localhost:11434/api/tags

# Проверка из эмулятора
adb shell curl http://10.0.2.2:11434/api/tags

# Тест чата через CLI
ollama run llama3.2:3b "Привет, как дела?"
```

### Шаг 4: Настройка в приложении

1. **Запустите приложение** на эмуляторе/устройстве
2. **Откройте настройки** (⚙️)
3. **Включите "Ollama Vector Search"**
   - Автоматически проверяется подключение к серверу
   - Автоматически загружается список доступных моделей
4. **Выберите локальную модель** из списка "Local Chat Model"
   - По умолчанию: `llama3.2:3b`
   - Доступны все установленные модели

### Шаг 5: Использование

**Сценарий 1: Обычный чат (без индексированных документов)**

**Сценарий 2: RAG чат (с индексированными документами)**

## Подводные камни и решения

### Проблема 1: Модель по умолчанию была embedding моделью

**Симптомы:**
- Ошибки при попытке использовать `nomic-embed-text` для чата
- Модель не может генерировать текстовые ответы

**Решение:**
- Изменен `DEFAULT_CHAT_MODEL` на `llama3.2:3b`
- Добавлена возможность выбора модели в UI

### Проблема 2: Ollama не работает без индексированных документов

**Симптомы:**
- При включенном Ollama, но без документов, приложение выдавало ошибку
- Нельзя было использовать Ollama для обычного чата

**Решение:**
- Добавлен метод `handleSendMessageWithOllamaChat()` для обычного чата
- Модифицирована логика: если нет документов → обычный чат через Ollama

### Проблема 3: Нельзя выбрать модель для чата

**Симптомы:**
- Всегда использовалась модель по умолчанию
- Нет возможности использовать другие установленные модели

**Решение:**
- Добавлен UI для выбора модели в настройках
- Автоматическая загрузка списка доступных моделей
- Сохранение выбранной модели в Preferences

### Проблема 4: Модели не устанавливаются автоматически

**Симптомы:**
- После установки Ollama нет моделей для чата
- Нужно вручную устанавливать модели

**Решение:**
- Обновлен `setup-ollama.sh` для установки моделей по умолчанию
- Создан `install-ollama-models.sh` для установки дополнительных моделей

### Проблема 5: Непонятно, какая модель используется

**Симптомы:**
- В ответах не указано, какая модель использовалась
- Сложно понять, работает ли локальная модель

**Решение:**
- Добавлена индикация в ответах: "С Ollama (локальная модель: [название])"
- В UI отображается выбранная модель

### Проблема 6: Ollama недоступен из эмулятора

**Симптомы:**
- Ошибки подключения к `http://localhost:11434`
- Эмулятор не может достучаться до Ollama на хосте

**Решение:**
- Использование специального IP `10.0.2.2` для эмулятора
- Настройка Network Security Config для cleartext traffic
- Отдельный OkHttp клиент для локальных адресов

## Принцип работы

### Архитектура

```
Android App (ChatViewModel)
    ↓
OllamaApi (Retrofit)
    ↓
Ollama Server (localhost:11434)
    ↓
Local LLM Models (llama3.2:3b, phi3:medium, etc.)
```

### Поток данных для обычного чата

1. Пользователь вводит сообщение
2. `ChatViewModel.handleSendMessage()` проверяет, включен ли Ollama
3. Если включен и нет документов → `handleSendMessageWithOllamaChat()`
4. Формируется список сообщений с историей (последние 10)
5. Отправляется запрос в `OllamaApi.generateChat()` с выбранной моделью
6. Ollama генерирует ответ через локальную LLM
7. Ответ отображается в UI с индикацией модели

### Поток данных для RAG чата

1. Пользователь вводит сообщение
2. `ChatViewModel.handleSendMessage()` проверяет, включен ли Ollama
3. Если включен и есть документы → `handleSendMessageWithOllama()`
4. Генерируется embedding запроса через `nomic-embed-text`
5. Выполняется векторный поиск похожих chunks
6. Опционально: reranking через `phi3:medium`
7. Формируется промпт с контекстом из chunks
8. Отправляется запрос в `OllamaApi.generateChat()` с выбранной моделью
9. Ollama генерирует ответ на основе контекста
10. Ответ отображается в UI с информацией о chunks
