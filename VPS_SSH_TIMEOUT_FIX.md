# Исправление ошибки SSH: Operation timed out

## Проблема

При попытке подключиться по SSH:
```bash
ssh root@109.73.194.244
```

Получаете ошибку:
```
ssh: connect to host 109.73.194.244 port 22: Operation timed out
```

## Причины

1. **Firewall блокирует входящие соединения на порт 22 (SSH)**
2. **SSH сервис не запущен на VPS**
3. **Проблемы с сетью**

## Решение

### Шаг 1: Проверьте firewall в панели управления VPS

**ВАЖНО:** Нужно разрешить **входящие** (incoming) соединения на порт 22!

1. **Откройте панель управления VPS**
2. **Перейдите на вкладку "Firewall" или "Брандмауэр"**
3. **Найдите секцию "Входящий трафик" (Incoming Traffic)**
4. **Проверьте, есть ли правило для порта 22:**
   - Если нет - добавьте новое правило
   - Если есть - проверьте, что оно активно

### Шаг 2: Добавьте правило для SSH (порт 22)

**В панели управления VPS:**

1. **Нажмите "Добавить правило" (Add Rule) или "Создать" (Create)**
2. **Настройте правило:**
   - **Тип:** Входящий трафик (Incoming Traffic)
   - **Протокол:** TCP
   - **Порт или диапазон портов:** `22`
   - **Действие:** Разрешить (Allow)
   - **Описание (опционально):** SSH access
3. **Сохраните правило**

**Пример настройки:**
- Направление: Входящий (Incoming)
- Протокол: TCP
- Порт: 22
- Действие: Разрешить

### Шаг 3: Используйте веб-консоль VPS для проверки SSH

Если SSH все еще не работает, используйте веб-консоль VPS:

1. **Откройте панель управления VPS**
2. **Найдите кнопку "Веб-консоль" (Web Console) или "Консоль" (Console)**
3. **Нажмите на кнопку - откроется терминал в браузере**
4. **Войдите в систему:**
   - Логин: `root`
   - Пароль: (найдите в панели управления VPS, см. `VPS_WEB_CONSOLE_LOGIN.md`)

### Шаг 4: Проверьте, запущен ли SSH сервис

**В веб-консоли VPS выполните:**

```bash
# Проверьте статус SSH сервиса
sudo systemctl status ssh
# Или для некоторых систем:
sudo systemctl status sshd
```

**Если SSH не запущен, запустите его:**

```bash
# Для Ubuntu/Debian:
sudo systemctl start ssh
sudo systemctl enable ssh

# Для CentOS/RHEL:
sudo systemctl start sshd
sudo systemctl enable sshd
```

### Шаг 5: Проверьте, слушает ли SSH порт 22

**В веб-консоли VPS выполните:**

```bash
# Проверьте, слушает ли SSH порт 22
sudo netstat -tlnp | grep :22
# Или:
sudo ss -tlnp | grep :22
```

**Должны увидеть что-то вроде:**
```
tcp  0  0  0.0.0.0:22  0.0.0.0:*  LISTEN  1234/sshd
```

Если порт не слушается - SSH не запущен или настроен на другой порт.

### Шаг 6: Проверьте настройки SSH (если нужно)

**В веб-консоли VPS проверьте конфигурацию SSH:**

```bash
# Проверьте конфигурацию SSH
sudo cat /etc/ssh/sshd_config | grep -E "^Port|^ListenAddress|^PermitRootLogin"
```

**Убедитесь, что:**
- `Port 22` (или другой порт, который вы используете)
- `PermitRootLogin yes` (если хотите подключаться как root)

**После изменения конфигурации перезапустите SSH:**

```bash
sudo systemctl restart ssh
# Или:
sudo systemctl restart sshd
```

### Шаг 7: Проверьте firewall на самом VPS (ufw/firewalld)

**В веб-консоли VPS проверьте локальный firewall:**

**Для Ubuntu/Debian (ufw):**
```bash
# Проверьте статус
sudo ufw status

# Если firewall активен, разрешите SSH
sudo ufw allow 22/tcp
sudo ufw reload
```

**Для CentOS/RHEL (firewalld):**
```bash
# Проверьте статус
sudo firewall-cmd --state

# Если firewall активен, разрешите SSH
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --reload
```

### Шаг 8: Проверьте доступность порта с вашего Mac

**С вашего Mac выполните:**

```bash
# Проверьте доступность порта 22
nc -zv 109.73.194.244 22
# Или:
telnet 109.73.194.244 22
```

**Если порт доступен, увидите:**
```
Connection to 109.73.194.244 port 22 [tcp/ssh] succeeded!
```

**Если порт недоступен:**
- Firewall в панели управления VPS все еще блокирует порт 22
- Или SSH сервис не запущен

## Альтернативное решение: Используйте веб-консоль

Если SSH все еще не работает, используйте веб-консоль VPS для всех операций:

1. **Откройте панель управления VPS**
2. **Найдите кнопку "Веб-консоль" (Web Console)**
3. **Используйте веб-консоль для:**
   - Установки Ollama
   - Настройки firewall
   - Запуска сервисов

Веб-консоль работает напрямую через панель управления и не требует SSH.

## Проверка после исправления

После настройки firewall и SSH попробуйте снова:

```bash
ssh root@109.73.194.244
```

**Должно запросить пароль** (не должно быть "Operation timed out").

## Важные замечания

1. **Входящий vs Исходящий трафик:**
   - **Входящий (Incoming):** Соединения из интернета к VPS (нужен для SSH)
   - **Исходящий (Outgoing):** Соединения из VPS в интернет (нужен для установки пакетов)

2. **Порт 22 по умолчанию:**
   - SSH использует порт 22 по умолчанию
   - Если изменили порт SSH, используйте новый порт в firewall

3. **Безопасность:**
   - После настройки SSH рекомендуется использовать ключи вместо пароля
   - Можно изменить порт SSH на нестандартный для дополнительной безопасности

## Заключение

Ошибка "Operation timed out" обычно означает, что firewall блокирует входящие соединения на порт 22. Добавьте правило для входящего TCP трафика на порт 22 в панели управления VPS, и SSH должен заработать.
