# Исправление: Ollama работает локально, но недоступен извне

## Текущая ситуация

✅ **Ollama работает локально:** `curl http://localhost:11434/api/tags` возвращает JSON
❌ **Ollama недоступен извне:** `curl http://109.73.194.244:11434/api/tags` не работает

## Причина

**Ollama слушает только на localhost (127.0.0.1), а не на всех интерфейсах (0.0.0.0)!**

Когда Ollama слушает только на `127.0.0.1:11434`, он доступен только с самого VPS сервера, но не из интернета.

## Решение

### Шаг 1: Проверьте, на каком интерфейсе слушает Ollama

**В веб-консоли VPS выполните:**

```bash
# Альтернатива для netstat (если netstat не установлен)
sudo ss -tlnp | grep 11434
# Или:
sudo lsof -i :11434
```

**Должны увидеть что-то вроде:**

**❌ НЕПРАВИЛЬНО (слушает только на localhost):**
```
LISTEN  0  4096  127.0.0.1:11434  0.0.0.0:*  users:(("ollama",pid=1234))
```

**✅ ПРАВИЛЬНО (слушает на всех интерфейсах):**
```
LISTEN  0  4096  0.0.0.0:11434  0.0.0.0:*  users:(("ollama",pid=1234))
```
ghbпри
### Шаг 2: Остановите текущий процесс Ollama

**Если Ollama запущен в терминале:**
- Нажмите `Ctrl+C` в терминале, где запущен `ollama serve`

**Если Ollama запущен через systemd:**
```bash
sudo systemctl stop ollama
```

### Шаг 3: Запустите Ollama на всех интерфейсах

**ВАЖНО:** Используйте переменную окружения `OLLAMA_HOST=0.0.0.0:11434`!

**В веб-консоли VPS выполните:**

```bash
OLLAMA_HOST=0.0.0.0:11434 ollama serve
```

**Оставьте этот терминал открытым!**

### Шаг 4: Проверьте снова

**В другом терминале веб-консоли VPS выполните:**

```bash
# Проверка интерфейса
sudo ss -tlnp | grep 11434
```

**Должно быть:**
```
LISTEN  0  4096  0.0.0.0:11434  0.0.0.0:*  users:(("ollama",pid=1234))
```

**Проверка локально:**
```bash
curl http://localhost:11434/api/tags
```

**Проверка извне (с вашего Mac):**
```bash
curl http://109.73.194.244:11434/api/tags
```

**Должен вернуться JSON с моделями!**

### Шаг 5: Настройка постоянного запуска через systemd

**Для постоянной работы (чтобы Ollama запускался автоматически):**

```bash
# Создайте директорию для конфигурации
sudo mkdir -p /etc/systemd/system/ollama.service.d

# Создайте файл конфигурации
sudo nano /etc/systemd/system/ollama.service.d/override.conf
```

**Добавьте в файл:**
```ini
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
```

**Сохраните файл:**
- Нажмите `Ctrl+O` (сохранить)
- Нажмите `Enter` (подтвердить имя файла)
- Нажмите `Ctrl+X` (выйти)

**Примените изменения:**
```bash
sudo systemctl daemon-reload
sudo systemctl enable ollama
sudo systemctl start ollama
sudo systemctl status ollama
```

**Проверьте снова:**
```bash
sudo ss -tlnp | grep 11434
```

Должно быть `0.0.0.0:11434`, а не `127.0.0.1:11434`.

## Альтернативные команды для проверки портов

**Если `netstat` не установлен, используйте:**

```bash
# Вариант 1: ss (Socket Statistics) - обычно установлен по умолчанию
sudo ss -tlnp | grep 11434

# Вариант 2: lsof (List Open Files)
sudo lsof -i :11434

# Вариант 3: Установите netstat
# Для Ubuntu/Debian:
sudo apt install net-tools
# Для CentOS/RHEL:
sudo yum install net-tools
```

## Проверка после исправления

**В веб-консоли VPS:**
```bash
# 1. Проверка интерфейса
sudo ss -tlnp | grep 11434
# Должно быть: 0.0.0.0:11434

# 2. Проверка локально
curl http://localhost:11434/api/tags
# Должен вернуться JSON
```

**С вашего Mac:**
```bash
# 3. Проверка извне
curl http://109.73.194.244:11434/api/tags
# Должен вернуться JSON
```

## Важные замечания

1. **OLLAMA_HOST=0.0.0.0:11434** - обязательно используйте эту переменную окружения при запуске Ollama!

2. **0.0.0.0 vs 127.0.0.1:**
   - `127.0.0.1:11434` - доступен только локально (с VPS)
   - `0.0.0.0:11434` - доступен из интернета (со всех IP адресов)

3. **Firewall:** Убедитесь, что входящее правило для порта 11434 разрешает доступ со всех адресов (не только с конкретного IP).

4. **Исходящее TCP правило:** Проверьте, что исходящее TCP правило в firewall имеет указанный порт (не пустое поле).

## Заключение

Проблема в том, что Ollama слушает только на localhost. После запуска с `OLLAMA_HOST=0.0.0.0:11434` Ollama должен стать доступным из интернета.
