## Как запустить и проверить работоспособность

### Шаг 1: Настройка окружения

1. **Установите Android Studio** (последняя версия)
2. **Убедитесь, что установлены**:
   - JDK 17 или выше
   - Android SDK (API 26-35)
   - Gradle 8.9+

### Шаг 2: Настройка API ключей

Создайте файл `local.properties` в корне проекта:

```properties
DEEPSEEK_API_KEY=your_deepseek_api_key_here
OPENROUTER_API_KEY=your_openrouter_api_key_here
```

**Где получить ключи**:
- DeepSeek: https://platform.deepseek.com/
- OpenRouter: https://openrouter.ai/ (для Claude, GPT, Gemini)

### Шаг 3: Проверка компиляции

```bash
cd /Users/Victor/work/hw-1-AI-chat-bot
./gradlew clean assembleDebug
```

**Ожидаемый результат**: `BUILD SUCCESSFUL`

### Шаг 4: Установка на устройство/эмулятор

**Через Android Studio**:
1. Откройте проект в Android Studio
2. Подключите устройство или запустите эмулятор
3. Нажмите Run (Shift+F10)

**Через командную строку**:
```bash
./gradlew installDebug
```

### Шаг 5: Проверка функционала

#### 5.1. Базовый чат
1. Откройте приложение
2. Выберите AI модель в верхней панели
3. Отправьте сообщение: "Привет, расскажи о себе"
4. **Ожидаемое**: AI отвечает, сообщение сохраняется в БД

#### 5.2. Персонализация
1. Отправьте: "Расскажи про Эверест"
2. **Ожидаемое**:
   - Создается профиль пользователя в БД
   - AI отвечает с учетом интереса к альпинизму
   - Может предложить связанные темы

3. Отправьте похожее: "Что нужно для восхождения?"
4. **Ожидаемое**:
   - Система находит похожий контекст
   - Используется тот же или похожий профиль
   - AI помнит предыдущий контекст

#### 5.3. Голосовой ввод
1. Нажмите кнопку микрофона (слева от кнопки отправки)
2. Разрешите доступ к микрофону (при первом использовании)
3. Скажите: "Посчитай 15 умножить на 7"
4. **Ожидаемое**:
   - Текст появляется в поле ввода в реальном времени
   - После распознавания автоматически отправляется
   - AI отвечает текстом

**Тестовые голосовые команды**:
- "Дай определение слова алгоритм"
- "Скажи анекдот"
- "Расскажи про искусственный интеллект"

#### 5.4. Сжатие контекста
1. Отправьте 10+ сообщений подряд
2. **Ожидаемое**:
   - После 10-го сообщения создается ContextSummary
   - Старые сообщения удаляются из БД
   - В UI отображается сводка "История обсуждений"

#### 5.5. Переключение моделей
1. Нажмите на название модели в верхней панели
2. Выберите другую модель (Claude, GPT, Gemini)
3. Отправьте то же сообщение
4. **Ожидаемое**:
   - Ответ от другой модели
   - Метрики сравнения обновляются
   - Можно сравнить качество ответов

#### 5.6. Экспорт истории
1. Отправьте несколько сообщений
2. Нажмите кнопку экспорта (иконка загрузки в верхней панели)
3. **Ожидаемое**:
   - Открывается диалог с TOON форматом
   - Можно скопировать в буфер обмена

#### 5.7. Просмотр базы данных
1. Нажмите кнопку базы данных (иконка хранилища в верхней панели)
2. **Ожидаемое**:
   - Отображается информация о БД:
     - Количество сообщений
     - Количество сводок
     - Количество пользователей
     - Количество контекстов

### Шаг 6: Проверка базы данных (Android Studio)

1. Запустите приложение в режиме отладки
2. В Android Studio: View → Tool Windows → App Inspection → Database Inspector
3. Найдите базу данных `chat_database`

## Принцип работы God Agent

### Поток данных при отправке сообщения

```
User Input (текст/голос)
    ↓
ChatViewModel.handleSendMessage()
    ↓
1. Сохранение сообщения в БД
    ↓
2. PersonalizeUserUseCase
    ├─→ Извлечение контекста через AI (5 слов)
    ├─→ Извлечение расширенного контекста
    ├─→ Извлечение имени пользователя
    └─→ McpContextService.findUserByContext()
        ├─→ Поиск в UserContextEntity
        ├─→ Если найдено → возврат существующего профиля
        ├─→ Если похоже → создание нового с похожим промптом
        └─→ Если ничего → создание нового профиля
    ↓
3. buildMessagesWithContext()
    ├─→ Добавление промпта персонализации
    ├─→ Добавление контекстных сводок (последние 3)
    ├─→ Добавление несжатых сообщений
    └─→ Добавление текущего сообщения
    ↓
4. SendMessageUseCase
    ├─→ Отправка в выбранную AI модель
    ├─→ Расчет метрик (время ответа, токены, стоимость)
    └─→ Создание Message с метриками
    ↓
5. Сохранение ответа в БД
    ↓
6. CompressionScheduler.onMessageSaved()
    ├─→ Проверка порога (10 сообщений)
    └─→ Если достигнут → сжатие через AI
    ↓
7. Обновление UI с ответом и метриками
```

### Поток данных при голосовом вводе

```
User нажимает кнопку микрофона
    ↓
HomeScreen.handleVoiceInputClick()
    ├─→ Проверка разрешения RECORD_AUDIO
    └─→ Если нет → запрос разрешения
    ↓
ChatViewModel.handleStartVoiceInput()
    ↓
SpeechRecognizerManager.startListening()
    ├─→ Создание SpeechRecognizer
    ├─→ Настройка Intent (ru-RU, частичные результаты)
    └─→ Запуск распознавания
    ↓
Flow<SpeechResult>
    ├─→ PartialResult → обновление currentInput в реальном времени
    ├─→ Success → автоматическая отправка через sendMessageFromVoice()
    └─→ Error → отображение через Snackbar
    ↓
sendMessageFromVoice() → тот же поток, что и при текстовом вводе
```

### Система персонализации (MCP-подобная логика)

```
User Message: "Расскажи про Эверест и как на него взобраться"
    ↓
PersonalizeUserUseCase.extractContext()
    ├─→ AI извлекает: "Про Эверест и восхождение"
    └─→ Нормализация: "про эверест и восхождение" (5 слов)
    ↓
McpContextService.findUserByContext()
    ├─→ Поиск точного совпадения в UserContextEntity
    ├─→ Если найдено → возврат UserProfile с существующим промптом
    ├─→ Поиск похожих контекстов (общие слова)
    │   └─→ Если найдено → создание нового профиля с похожим промптом
    └─→ Если ничего → создание нового профиля с базовым промптом
    ↓
Генерация промпта персонализации:
    "Пользователь интересуется альпинизмом и восхождениями на горы. 
     Особенно интересуется Эверестом. Предпочитает подробные ответы 
     с практическими советами. Предлагай связанные темы: другие горы, 
     снаряжение, техники восхождения."
    ↓
Промпт добавляется в системное сообщение
    ↓
AI отвечает с учетом персонализации
```

### Автоматическое сжатие контекста

```
Каждое сообщение → CompressionScheduler.onMessageSaved()
    ↓
Счетчик сообщений (отдельно для user и AI)
    ↓
При достижении 10 сообщений:
    ├─→ Получение последних 10 сообщений из БД
    ├─→ Создание промпта для AI
    ├─→ Отправка в AI для создания summary
    ├─→ Парсинг JSON: { "summary": "...", "key_facts": [...] }
    ├─→ Fallback на FallbackSummarizer при ошибке
    ├─→ Создание ContextSummary
    ├─→ Сохранение в БД
    ├─→ Удаление оригинальных сообщений
    └─→ Обрезка до 5 сводок на роль
    ↓
ContextSummary используется в buildMessagesWithContext()
    для предоставления контекста AI без загрузки всех сообщений
```

## Решение проблем

### Проблема: Компиляция не проходит

**Решение**:
1. Проверьте версию Gradle: `./gradlew --version`
2. Синхронизируйте проект: File → Sync Project with Gradle Files
3. Очистите кэш: `./gradlew clean`
4. Пересоберите: `./gradlew build`

**Если ошибки с WorkManager**:
- Убедитесь, что в `gradle/libs.versions.toml` добавлена версия `work = "2.9.0"`
- Убедитесь, что в `app/build.gradle.kts` и `feature/chat/build.gradle.kts` добавлена зависимость `implementation(libs.work.runtime.ktx)`

**Если ошибки с DTO классами**:
- Проверьте, что в `ChatRequest.kt` есть все классы: `ToolDto`, `ToolFunctionDto`, `ToolParametersDto`, `ToolPropertyDto`

### Проблема: API ключи не работают

**Решение**:
1. Проверьте `local.properties` - ключи должны быть без кавычек
2. Пересоберите проект после изменения ключей
3. Проверьте, что ключи действительны на соответствующих платформах

### Проблема: Голосовой ввод не работает

**Решение**:
1. Проверьте разрешение RECORD_AUDIO в настройках приложения
2. Убедитесь, что Google Speech Services установлены
3. Проверьте подключение к интернету (для некоторых устройств требуется)
4. Проверьте, что микрофон работает в других приложениях

### Проблема: Персонализация не работает

**Решение**:
1. Проверьте логи в `PersonalizeUserUseCase`
2. Убедитесь, что API ключ DeepSeek настроен (используется для извлечения контекста)
3. Проверьте БД через Database Inspector - должны быть записи в `users` и `user_contexts`

### Проблема: Сжатие контекста не происходит

**Решение**:
1. Отправьте минимум 10 сообщений
2. Проверьте логи в `CompressionScheduler`
3. Убедитесь, что AI модель доступна для создания сводок
4. Проверьте БД - должны появиться записи в `context_summaries`

### Проблема: Приложение крашится

**Решение**:
1. Проверьте логи в Logcat
2. Убедитесь, что все зависимости установлены
3. Проверьте версию Android SDK (минимум API 26)
4. Очистите данные приложения и переустановите

### Проблема: Ошибки миграции базы данных

**Решение**: 
База данных настроена с `fallbackToDestructiveMigration(true)`, что означает, что при изменении схемы БД данные будут удалены. Для production следует создать миграцию:

```kotlin
val MIGRATION_5_6 = object : Migration(5, 6) {
    override fun migrate(database: SupportSQLiteDatabase) {
        database.execSQL("CREATE TABLE IF NOT EXISTS vectors (id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL, chunk_text TEXT NOT NULL, embedding TEXT NOT NULL, source_file TEXT NOT NULL, file_hash TEXT NOT NULL, chunk_index INTEGER NOT NULL, created_at INTEGER NOT NULL)")
        database.execSQL("CREATE TABLE IF NOT EXISTS indexed_books (book_id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL, title TEXT NOT NULL, file_hash TEXT NOT NULL, file_path TEXT, chunk_count INTEGER NOT NULL, timestamp INTEGER NOT NULL)")
        database.execSQL("CREATE TABLE IF NOT EXISTS book_chunks (chunk_id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL, book_id INTEGER NOT NULL, chunk_index INTEGER NOT NULL, chunk_text TEXT NOT NULL, embedding TEXT NOT NULL, created_at INTEGER NOT NULL, FOREIGN KEY(book_id) REFERENCES indexed_books(book_id) ON DELETE CASCADE)")
        database.execSQL("CREATE INDEX IF NOT EXISTS index_vectors_source_file ON vectors(source_file)")
        database.execSQL("CREATE INDEX IF NOT EXISTS index_book_chunks_book_id ON book_chunks(book_id)")
    }
}
```
