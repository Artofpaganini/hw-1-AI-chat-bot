# Исправление ошибки: Connection refused (ECONNREFUSED)

## Проблема

При попытке обратиться к VPS Ollama из Android приложения возникает ошибка:
```
Network IO error for VPS - Ollama: llama3.2:3b
ConnectException: failed to connect to /109.73.194.244 (port 11434) from /10.0.2.16 (port 42582) after 60000ms: isConnected failed: ECONNREFUSED (Connection refused)
```

## Причина

**Ошибка `ECONNREFUSED` означает, что соединение отклонено сервером.**

Возможные причины:
1. **Ollama не запущен на VPS**
2. **Ollama слушает только на localhost (127.0.0.1), а не на всех интерфейсах (0.0.0.0)**
3. **Firewall блокирует входящие соединения на порт 11434**
4. **Проблемы с сетью между эмулятором и VPS**

## Пошаговая диагностика

### Шаг 1: Проверьте, запущен ли Ollama на VPS

**В веб-консоли VPS выполните:**

```bash
ps aux | grep ollama | grep -v grep
```

**Если процесс не найден:**
- Ollama не запущен
- Запустите Ollama: `OLLAMA_HOST=0.0.0.0:11434 ollama serve`
- Оставьте этот терминал открытым

**Если процесс найден:**
- Ollama запущен
- Переходите к Шагу 2

### Шаг 2: Проверьте, на каком интерфейсе слушает Ollama

**В веб-консоли VPS выполните:**

```bash
sudo ss -tlnp | grep 11434
# Или:
sudo lsof -i :11434
```

**Должны увидеть что-то вроде:**

**✅ ПРАВИЛЬНО (слушает на всех интерфейсах):**
```
LISTEN  0  4096  0.0.0.0:11434  0.0.0.0:*  users:(("ollama",pid=1234))
```

**❌ НЕПРАВИЛЬНО (слушает только на localhost):**
```
LISTEN  0  4096  127.0.0.1:11434  0.0.0.0:*  users:(("ollama",pid=1234))
```

**Если видите `127.0.0.1:11434` вместо `0.0.0.0:11434`:**

1. Остановите текущий процесс Ollama (Ctrl+C в терминале, где он запущен)
2. Запустите снова: `OLLAMA_HOST=0.0.0.0:11434 ollama serve`
3. Проверьте снова: `sudo ss -tlnp | grep 11434`

### Шаг 3: Проверьте доступность Ollama локально (с VPS)

**В веб-консоли VPS выполните:**

```bash
curl http://localhost:11434/api/tags
```

**Если работает:**
- Ollama запущен и работает локально
- Переходите к Шагу 4

**Если не работает:**
- Ollama не запущен или не слушает на правильном интерфейсе
- Вернитесь к Шагу 1 или Шагу 2

### Шаг 4: Проверьте доступность Ollama извне (с вашего Mac)

**С вашего Mac выполните:**

```bash
curl http://109.73.194.244:11434/api/tags
```

**Если работает:**
- Ollama доступен из интернета
- Проблема может быть в настройках эмулятора или сети
- Переходите к Шагу 5

**Если не работает:**
- Проблема в firewall или настройке Ollama
- Переходите к Шагу 6

### Шаг 5: Проверьте firewall на VPS

**В панели управления VPS:**

1. Перейдите на вкладку "Сети" → "Firewall"
2. Найдите группу правил для входящего трафика
3. Проверьте, есть ли правило для порта 11434:
   - **Направление:** Входящий (Inbound/Incoming)
   - **Протокол:** TCP
   - **Порт:** `11434`
   - **Адрес:** Все адреса (All addresses)
   - **Действие:** Разрешить (Allow)

4. **Если правила нет - создайте его:**
   - Нажмите "+ Добавить" или "Создать"
   - Настройте как указано выше
   - Сохраните и примените правило

5. **Проверьте, что правило применено:**
   - В списке правил должно быть видно правило для порта 11434
   - Статус должен быть "Активно" или "Применено"

### Шаг 6: Проверьте доступность VPS из эмулятора

**С вашего Mac выполните (через adb):**

```bash
# Проверка доступности VPS из эмулятора
adb shell curl http://109.73.194.244:11434/api/tags
```

**Если работает:**
- VPS доступен из эмулятора
- Проблема может быть в настройках приложения или таймаутах

**Если не работает:**
- Проблема в сетевых настройках эмулятора
- Проверьте настройки сети эмулятора в Android Studio

### Шаг 7: Проверьте настройки приложения

**В Android приложении:**

1. Откройте настройки (⚙️)
2. Найдите секцию "VPS Ollama Configuration"
3. Проверьте, что URL введен правильно:
   - Должен быть: `http://109.73.194.244:11434`
   - НЕ должен быть: `http://10.0.2.2:11434` (это для локального Ollama)
   - НЕ должен быть: `https://109.73.194.244:11434` (если не настроен SSL)

4. Сохраните настройки
5. Выберите модель "VPS - Ollama: llama3.2:3b"
6. Проверьте индикатор модели (должен быть зеленым)

## Наиболее вероятные причины

### Причина 1: Ollama не запущен

**Симптомы:**
- `ps aux | grep ollama` не находит процесс
- `curl http://localhost:11434/api/tags` не работает

**Решение:**
```bash
OLLAMA_HOST=0.0.0.0:11434 ollama serve
```

### Причина 2: Ollama слушает только на localhost

**Симптомы:**
- `sudo ss -tlnp | grep 11434` показывает `127.0.0.1:11434`
- `curl http://localhost:11434/api/tags` работает
- `curl http://109.73.194.244:11434/api/tags` не работает

**Решение:**
```bash
# Остановите текущий процесс
pkill ollama

# Запустите на всех интерфейсах
OLLAMA_HOST=0.0.0.0:11434 ollama serve
```

### Причина 3: Firewall блокирует порт 11434

**Симптомы:**
- Ollama запущен и слушает на `0.0.0.0:11434`
- `curl http://localhost:11434/api/tags` работает
- `curl http://109.73.194.244:11434/api/tags` не работает

**Решение:**
- Проверьте firewall в панели управления VPS
- Убедитесь, что порт 11434 открыт во входящих правилах
- См. `VPS_FIREWALL_SETUP.md`

### Причина 4: Проблемы с сетью эмулятора

**Симптомы:**
- `curl http://109.73.194.244:11434/api/tags` работает с Mac
- `adb shell curl http://109.73.194.244:11434/api/tags` не работает

**Решение:**
- Проверьте настройки сети эмулятора в Android Studio
- Перезапустите эмулятор
- Проверьте DNS настройки эмулятора

## Проверка после исправления

**После исправления всех проблем:**

1. **В веб-консоли VPS:**
   ```bash
   # Проверка интерфейса
   sudo ss -tlnp | grep 11434
   # Должно быть: 0.0.0.0:11434
   
   # Проверка локально
   curl http://localhost:11434/api/tags
   # Должен вернуться JSON
   ```

2. **С вашего Mac:**
   ```bash
   # Проверка извне
   curl http://109.73.194.244:11434/api/tags
   # Должен вернуться JSON
   ```

3. **В Android приложении:**
   - Откройте настройки (⚙️)
   - Проверьте URL: `http://109.73.194.244:11434`
   - Выберите модель "VPS - Ollama: llama3.2:3b"
   - Проверьте зеленый индикатор
   - Отправьте тестовое сообщение

## Заключение

**Основные причины ошибки `ECONNREFUSED`:**
1. Ollama не запущен на VPS
2. Ollama слушает только на localhost (127.0.0.1)
3. Firewall блокирует входящие соединения на порт 11434

**После исправления всех проблем:**
- Ollama должен быть запущен с `OLLAMA_HOST=0.0.0.0:11434`
- Порт 11434 должен быть открыт в firewall
- Ollama должен быть доступен из интернета

После исправления модель должна работать корректно.
